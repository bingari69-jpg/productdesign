# 제품 디자이너 스킬의 작동 원리

이 스킬은 별도로 학습된 디자인 모델이나 독립 실행 앱이 아니라, Codex가 디자인 작업을 할 때 읽는 판단 지침과 참고 문서입니다. 실행 주체는 AI이며 조사·이미지 관찰·코드 작성·이미지 생성·검증 도구를 요청에 맞게 조합합니다.

## 선택과 문서 읽기

먼저 스킬 이름과 설명으로 요청과의 관련성을 판단합니다. 명시적으로 `$product-designer`를 부르면 해당 지침을 사용합니다. 전체 설계 규칙은 SKILL.md에 있고, 필요한 분야의 상세 문서만 추가로 읽습니다.

- 웹·앱이면 `digital.md`: 사용 흐름·화면 상태·반응형·접근성·구현.
- 실물이면 `physical.md`: 치수·재료·공정·부품·조립·시제품.
- 결합 제품이면 둘 다: 물리 조작·앱 상태·연결 실패까지 연결.
- 공통은 `research-and-reference.md`와 `verification.md`.
- `sources.md`는 조사 출발점이며 최신 사양을 자동 갱신하는 데이터베이스가 아닙니다.
- 용량·체결·간섭·CAD 출력이 필요하면 `cad-handoff.md`를 읽고 기존 CAD 또는 CadQuery·build123d 연결 경로를 검토합니다. 도구를 자동 설치하는 기능은 아닙니다.

이렇게 필요한 내용을 단계적으로 읽는 구조는 [OpenAI 공식 문서의 스킬 설명](https://learn.chatgpt.com/docs/build-skills)과 같습니다. 스킬에 들어 있는 링크를 매번 전부 검색하는 고정 자동화는 아닙니다.

## 설계 판단 순서

| 단계 | 판단 | 결과 |
|---|---|---|
| 1. 범위 | 누가 무엇에 쓰는가, 새 제품인가 수정인가, 무엇을 유지해야 하는가 | 목적·제약·미정 가정 |
| 2. 근거 | 실제 이미지에 무엇이 보이는가, 유사 제품·구현·공정은 무엇인가 | 관찰·출처·확인 한계 |
| 3. 원리 | 좋아하는 인상을 만드는 비례·색·질감·사용 동작은 무엇인가 | 새 디자인에 적용할 규칙 |
| 4. 대안 | 구조·조작·형태가 어떻게 달라질 수 있는가 | 보통 2~3개 방향과 추천 이유 |
| 5. 구체화 | 현재 환경에서 어떤 도구·원본 형식으로 만들어야 하는가 | 프로토타입·시안·사양 |
| 6. 검토 | 실제 결과가 요청과 맞는가, 기능·제작에 모순은 없는가 | 확인 결과·수정·남은 검증 |
| 7. 피드백 | 사용자가 어느 부분을 어떻게 바꾸려 하는가 | 지정 범위의 다음 버전 |

사용자가 방향을 정하면 대안을 다시 강요하지 않습니다. 버튼 크기나 의자 날개만 수정할 때 전체 제품 조사를 반복하지 않습니다.

## 이미지 생성으로 연결하는 방법

이미지 자체를 모델 학습 데이터로 추가하는 것이 아니라 해당 작업의 입력으로 전달합니다. 편집 대상 이미지와 형태·소재 참고 이미지를 구분하고 프롬프트에 다음을 적습니다.

1. 바꿀 부분: 예를 들어 어깨 날개의 폭·앞 돌출.
2. 유지할 부분: 머리 형태·좌판·소재·팔걸이·두 뷰 구성.
3. 제작 조건: 철재 프레임+폼+봉제, 새 플라스틱 셸 제외 등.
4. 결과 형식: 시점·배경·필요한 뷰·표현 재료.
5. 피할 결과: 요청하지 않은 바퀴·발받침·추가 부품 등.

생성 후 이미지를 실제로 보고 요청에 맞는지 확인합니다. 이미지 모델은 지정하지 않은 부분도 바꾸거나 미세한 구조를 일관되게 그리지 못할 수 있어, 결과를 보고 제한된 수정을 다시 요청합니다. 픽셀 고정·3D 정합·치수·기구 작동을 자동 보장하지 않습니다.

## 이번 작업에서 실제로 드러난 점

의자 초반에는 생산 제약을 파악하기 전에 새 플라스틱 셸과 메쉬 프레임을 제안하는 실수가 있었습니다. 사용자가 기존 철재 프레임에 폼을 입히는 방식을 지정한 뒤 그 제약을 제품 기록에 명시하고 다음 시안에 반영했습니다. 이는 현재 절차가 제약을 자동 탐지하거나 실수를 완전히 차단하는 시스템이 아님을 보여줍니다.

2026-10-31 보강에서는 이런 조건을 다음 시안 전에 프로젝트 메모로 정리하도록 명시했습니다. 실물의 새 설계는 형태 대안·정면/측면·내부 공간·기구·재료를 연결하고, 작동이 확인되지 않은 부분을 렌더 전에 드러냅니다. 작은 수정과 빠른 외형 시안에는 전체 절차나 매 단계 승인을 강제하지 않습니다.

칫솔에서는 열린 손잡이 형태를 먼저 만들고, 사용자의 치약 수납·교체형 헤드 요청을 기능 구조로 바꿨습니다. 탈착 치약 포드·헤드 잠금·통풍 보호캡은 구현 제안이며, 누수·용량·결합 강도는 시험 전입니다. 치약 수납과 교체형 헤드를 갖춘 기존 제품도 있어 최초 발명으로 주장하지 않습니다.

## 현재 포함되지 않은 기능

- 자동 CAD 생성·금형 해석·구조 해석 엔진.
- 고정 점수로 통과를 판정하는 독립 품질 게이트.
- 사용자 조사·실제 착좌·칫솔 사용·누수 시험의 자동 수행.
- 특허 신규성·디자인권·양산 원가의 자동 판정.
- 대화마다 자동으로 학습·수정되는 모델. 현재 피드백은 해당 프로젝트 기록과 시안에 반영하며, 스킬의 장기 규칙을 고치는 작업은 별도입니다.

현재 이 스킬의 강점은 설계 판단을 일정한 순서로 정리하고 관찰·가정·실측을 구분하는 것입니다. 생성 시안은 제작 논의를 위한 출발점이며, 제조 가능한 확정 설계로 발전시키려면 실제 도면과 시제품 검토가 필요합니다.
