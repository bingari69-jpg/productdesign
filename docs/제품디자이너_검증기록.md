## 사용자 요청 반영

- 웹·앱과 실물 제품 중 선택 가능하며 결합 제품도 지원한다.
- 사용자가 제공한 이미지·스타일·자료를 관찰해 새로운 디자인으로 발전시킨다.
- 실용성과 구현·제작을 결과 기준으로 삼는다.
- GitHub 구현·실제 제품 문서·연구·디자인 시스템·제조 지침을 조사했다. 출처 27개와 확인 범위는 스킬의 references/sources.md에 있다.

## 실제 실행한 검사

- 작업실 가상환경 Python으로 공식 quick_validate.py 실행: `Skill is valid!`
- Windows 기본 인코딩 문제를 피하려고 Python `-X utf8`로 검사했다. 시스템 Python에는 PyYAML이 없어 기존 작업실 환경을 사용했고 추가 설치는 하지 않았다.
- Markdown 내부 상대 링크 5개 존재 확인: 통과.
- UI YAML 파싱, 소개문 길이, 호출명, 기본 자동 선택 정책 확인: 통과.
- 미완성 scaffold 표시 확인: 없음.
- 설치 파일: SKILL.md, agents/openai.yaml, references/ 아래 5개 문서.

## 수동 시나리오 검토

실제 사용자 세션을 재실행한 실험이 아니라 작성자가 요청별 적용 경로와 충돌을 점검한 결과다.

| 요청 | 확인한 적용 경로·판단 | 결과 |
|---|---|---|
| 사진 분위기의 예약 앱 | 분야 재질문 없이 이미지 분석 → digital → 예약 상태·변경·복구 | 해당 지침 존재 |
| 조약돌 느낌 스피커, 예산 미정 | 가정 명시 → 대안 → physical → 부품·조립·시제품/양산 구분 | 해당 지침 존재 |
| 화려한 유리 UI | 취향 유지 → 대비·동작·reduced-motion 검토 | 일률적 미적 금지 없음 |
| 기존 버튼 크기만 수정 | 현재 코드·브랜드 확인 → 요청 범위 수정 → 실제 화면 검증 | 전체 재설계 강요 없음 |
| 사진만으로 정확한 STEP 요청, CAD 없음 | 사진의 한계 → 치수 초안·편집 소스 → 미실행 명시 | 허위 CAD 완료 방지 |
| 가구와 제어 앱 | 두 분야 문서 → 물리/앱 우선순위·연결 실패 → 구조 검토 | 결합 경로 존재 |

## 확인하지 않은 사항

실제 프로젝트에서 스킬 자동 선택 여부, 별도 모델의 독립 실행 평가, 디자인 시안 생성과 사용자 과업 시험, CAD 렌더링·시제품·제조사 검토는 아직 수행하지 않았다. 파일 검증 통과를 디자인 실력이나 양산 가능성의 보증으로 표현하지 않는다.

## 저장 위치와 사용 예

- 작업실 보관본: `지식/스킬/product-designer/`
- 이 컴퓨터 설치본: `C:/Users/USER/.codex/skills/product-designer/`
- GitHub commit·push는 수행하지 않았다.

호출 예:

> $product-designer 이 이미지 분위기로 예약 웹앱을 디자인해줘. 모바일에서 쓰기 편하고 실제로 동작하는 시안으로 만들어줘.

> $product-designer 이 사진의 형태와 질감을 참고해서 새로운 탁상 수납함을 디자인해줘. 소량 제작 기준으로 재료, 치수, 부품과 조립 방법까지 제안해줘.

현재 버전의 검증 한계를 유지하고 실제 사용에서 관찰한 실패를 근거로 좁게 개선한다. 사용자 취향이나 시행착오 하나를 모든 제품의 보편 규칙으로 만들지 않는다.

## 2026-10-31 보강과 재검증

사용자가 GitHub 조사 결과를 우리 스킬에 보태도록 요청했다. 형태 대안·정면/측면·내부 공간·기구 검토, 생산 제약 기록, 공정 비용 비교, CAD 연결, 웹·앱 비평·조사 구분을 보강했다. 외부 스킬의 전문·코드·고정 승인 단계는 이식하지 않았다. 출처는 27개에서 35개로 확장했다.

실행한 검사: 공식 quick_validate.py `Skill is valid!`, 스킬 내부 상대 링크 7개 존재, UI YAML·호출명·자동 선택 정책·미완성 표시 검사 통과, git diff 공백 오류 없음. 설치본과 작업실 보관본이 변경 전 저장소 기준과 같음을 확인해 기존 개인 수정을 덮어쓰지 않았다.

작성자가 새 지침을 네 요청에 수동 대조했다: 기존 철재 의자의 날개만 축소, 치약 용량·교체 헤드 추가, CAD 없는 환경의 정확한 용량 요구, 빠른 스타일 시안. 각각 범위 유지·공간/기구 검토·미실행 구분·전체 승인 절차 생략으로 연결된다. 이는 독립 실행 평가나 실제 제품 테스트가 아니다.

새 CAD 도구 설치·CAD 파일 생성·공정비 견적·실물 시제품 시험은 수행하지 않았다. 따라서 추가 가이드는 실행 경로이며 자동 CAD 엔진이나 제조 적합성 판정기의 구현으로 보고하지 않는다.
