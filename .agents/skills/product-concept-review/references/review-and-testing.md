# 평가 기록과 소비자 반응 확인

## 중립 전달 묶음

`시안 파일/버전 / 대상 소비자 / 사용 상황 / 제안 기능 / 기존 대체재 / 확정 제약 / 확인된 근거 / 가정 / 요청 범위(평가만 또는 수정 포함)`
디자이너의 추천 순서·자기 점수·유도 문구는 첫 묶음에서 제외한다. 소비자 발언은 원문 출처·제품 버전·상황을 붙이고 요약과 구분한다. 긍정·부정 의견과 서로 다른 사용자 집단을 함께 본다.

## 피드백을 판단으로

`항목 ID / 해당 부위·기능 / 근거 종류·출처 / 예상 영향 / 제안 / 잃을 수 있는 매력 / 수용·보류·기각 / 수정본 확인`
기능 추가가 가치보다 설정·관리 부담을 키우는지 본다. 손잡이는 편의뿐 아니라 휴대 장면·오브제 인상의 일부일 수 있다. 반대로 실제 이동 맥락이 없으면 손잡이의 필요성은 가설이다. 새로운 사용 장면을 상상하는 것은 허용하되 관찰된 수요라고 쓰지 않는다.

## 실제 사람에게 확인할 때

목표 사용자와 모집 경로·참여자 수·조건을 기록한다. 작은 편의 표본을 대표 시장으로 일반화하지 않는다. 실제 배포·모집·결제는 요청된 범위에서만 실행한다.

1. 짧게 보여준 뒤 어떤 제품이고 무엇이 가장 눈에 띄었는지 자유 응답을 받는다.
2. 설명을 동일하게 제공한 뒤 어느 상황에 쓰겠는지, 현재 무엇으로 해결하는지 묻는다.
3. 대안 순서를 바꾸거나 무작위화하고, 아무것도 선택하지 않음/기존 제품 유지도 허용한다. 가능하면 원본도 포함한다.
4. 외관 선호·기능 이해·사용 의향·가격 조건의 구매 의향을 분리한다. 선택 이유와 구매하지 않을 이유를 함께 묻는다. 손잡이가 편리하죠 같은 질문을 피한다.
5. 핵심 기능과 외관 중 무엇 때문인지 분리하려면 같은 외관에서 기능 설명을 바꾸거나 같은 기능의 외관 대안을 비교한다. 실험 조건을 기록한다.

실제 사용성은 이미지 선호로 입증할 수 없다. AI 페르소나 반응은 질문 탐색용 가설이며 모집된 사람의 응답으로 보고하지 않는다. 예쁜 렌더의 우위와 제품 개념의 우위를 구분한다. 구매 의향은 실제 구매/매출이 아니다.
