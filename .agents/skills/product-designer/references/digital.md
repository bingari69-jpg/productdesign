# 웹·앱 디자인과 구현

## 과업과 상태

핵심 과업을 사용자 말로 적고 진입·선택/입력·검토·실행·결과/복구를 연결한다. 모든 서비스에 같은 단계를 강제하지 않는다. 마케팅 페이지와 로그인 후 작업 도구의 목적을 구분한다.

화면 목록보다 과업 완료 조건을 먼저 정한다. 예약 버튼의 존재보다 시간을 찾고 예약을 확정·변경할 수 있는지가 중요하다. 시연 데이터는 실제 연동 데이터와 구분한다.

주요 화면에 역할·핵심 정보·주 행동·다음 화면·필요 데이터·복구를 연결한다.

| 상태 | 설계 내용 |
|---|---|
| 처음·빈 상태 | 이유와 첫 행동 |
| 로딩·진행 | 피드백·중복 실행 방지·취소 가능 여부 |
| 정상 | 읽는 순서와 핵심 작업 |
| 입력 오류·실패 | 원인·수정 위치·재시도·입력 보존 |
| 권한 없음·로그아웃 | 필요한 권한과 복귀 |
| 긴 내용·대량 데이터 | 줄바꿈·검색·분할·필요 시 가상화 |
| 저장·결제 결과 | 서버 확정·반영 시점·실패 복구 |

범위에 해당하는 상태를 구현한다. 로그인·결제·서버가 없는 시안에 실제 연동을 주장하지 않는다. 낙관적 업데이트에는 실패 시 되돌리기와 정합성을 설계한다.

## 시각 체계

레퍼런스의 팔레트·서체·밀도·모서리·구조를 토큰과 컴포넌트에 연결한다. 색의 역할을 본문·약한 정보·배경·행동·경고 등으로 정의한다. 글꼴은 실제 사용 가능 여부·한국어 글리프·라이선스를 확인한다.

같은 카드·그라데이션·대형 제목을 모든 제품에 반복하지 않는다. 사용자가 원하면 의도대로 쓴다. 새로움은 정보 이해와 조작 가능성을 유지하는 범위에서 만든다. 기존 제품은 디자인 시스템과 사용자 학습을 고려한다.

현실적인 길이의 한국어 문구로 설계한다. 버튼은 실행 결과를 예측할 수 있게 쓴다. 가격·후기·사용자 수 같은 신뢰 근거를 임의로 만들지 않는다.

반응형은 단순 축소 대신 콘텐츠 우선순위·탐색·목록/상세 배치를 조정한다. 사용 가능한 공간과 과업을 기준으로 한다. 네이티브 앱은 해당 플랫폼의 최신 공식 패턴과 단위를 확인한다.

## 접근성

웹 기본 목표는 적용 범위 내 WCAG 2.2 AA다. 계약·지역 기준은 별도 확인한다. 일부 체크 통과를 전체 준수 인증으로 보고하지 않는다.

- 텍스트 대비 4.5:1, 큰 텍스트 3:1, 필수 UI 경계·상태 등 비텍스트 대비 3:1의 적용 조건을 확인한다. 투명도·상태·규정상 예외를 구분한다.
- AA 포인터 대상 기준은 24×24 CSS px 또는 규정된 예외다. 터치 UI에는 약 44px 이상의 여유 영역을 설계 목표로 삼을 수 있지만 모든 플랫폼의 동일 규격이라고 주장하지 않는다.
- 키보드로 핵심 흐름을 완료하며 포커스가 보이고 가려지지 않아야 한다. 모달의 진입·이동·종료·복귀 포커스를 확인한다.
- 네이티브 HTML 의미 구조·명시적 레이블·오류 연결·상태 알림을 우선한다. 드래그·제스처에 필요한 대체 입력을 제공한다.
- 확대·텍스트 확장·좁은 화면·색 이외 상태 표시·reduced-motion을 고려한다.
- APCA 등 보조 지표를 WCAG AA 대비 판정 대신 쓰지 않는다. 포커스 외형 AAA 추가 기준과 AA 필수 기준을 구분한다.

## 구현과 전달

저장소의 프레임워크·설치된 컴포넌트·빌드 명령부터 확인한다. Radix·React Aria 등은 접근 가능한 기본 동작의 후보이며 자동 설치 대상이 아니다. shadcn/ui 등 기본 외형도 사용자 방향에 맞춘다.

편집 가능한 프로토타입의 핵심 버튼·폼·탭은 실제 상태 전환을 하게 한다. 스타일만 있으면 시각 시안으로 표시한다. 실제 서버 요청은 데이터 모델·API 계약·인증·오류 처리를 확인해 범위를 정한다.

전달물은 실행 방법·토큰·핵심 컴포넌트/상태·반응형 규칙·연결 데이터와 미연결 부분·검증 결과다. 작은 수정에 별도 문서 묶음을 강제하지 않는다.

브라우저에서 대표 모바일·데스크톱 폭과 구조 전환 경계를 실제 확인한다. 성능은 측정할 때만 보고한다. LCP·INP·CLS 필드 데이터와 로컬 진단을 구분하며 단일 로컬 측정을 실제 사용자 환경의 통과 증거로 삼지 않는다.
