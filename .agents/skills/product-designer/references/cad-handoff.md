# 콘셉트에서 CAD 검토로

용량·벽두께·부품 결합·이동·간섭·출력용 모델 또는 실제 CAD가 필요할 때 읽는다. 빠른 외형 시안마다 CAD를 만들지 않는다.

## 도구 선택

- 기존 CAD 파일·도구가 있으면 그 형식과 매개변수 체계를 우선한다.
- **CadQuery:** Python 기반 매개변수 모델·부품 조립·STEP 등의 전달 후보.
- **build123d:** Python 기반 곡선·스케치·솔리드의 조합과 매개변수 모델 후보.
- 하나의 작업에 둘 다 도입할 필요는 없다. 설치된 버전·공식 API·내보내기 기능을 확인한다. 현재 환경에서 가능한 경로를 택하며 새 환경 설치는 요청 범위와 설치 권한에 따른다. 다른 CAD·유료 서비스를 임의로 필수화하지 않는다.

## 입력과 모델링

`매개변수 / 단위 / 값 / 근거 / 사용자 확정·가정·미확인 / 연관 부품`을 둔다. 모르는 치수는 가정으로 시작할 수 있으나 도면에도 표시한다. 이미지 픽셀이나 생성된 치수 문자를 실측 근거로 쓰지 않는다.

기준 좌표·정면 방향·단위·부품 ID를 고정한다. 외부 형상과 내부 구조를 나누고 주 형상 → 내용물·부품 공간 → 벽·체결·동작 경로 → 세부 순서로 필요한 만큼 모델링한다. 가장 중요한 결합과 공간을 장식보다 먼저 본다. 시각용 형상과 기능 검토용 형상이 다르면 기록한다.

### 용량

내용물이 차지할 수 있는 내부 솔리드를 따로 정의한다. 부피가 mm³이면 1,000으로 나누면 mL다. 이 값은 기하학적 용량이며 공기 여유·잔류량·압출 변형·충전 한계를 반영한 사용 가능 용량과 구분한다. 내부 형상·재료·압출 조건이 미정이면 사용 횟수를 확정하지 않는다.

### 교체·움직임

정상 결합 외에 분리 경로·회전/슬라이드 끝 위치를 확인한다. 움직이는 부품은 중간 위치나 이동 공간도 검토해 끝 위치에서만 보이지 않는 간섭을 찾는다. 결합·치수 변경 후에는 영향을 받는 검사와 뷰를 다시 출력한다. 키·잠금·여유·공구 접근을 모델로 검토한다. 허용차와 물성이 없는 모델에서 스냅핏 힘·밀폐·피로 수명을 판정하지 않는다. 중요한 치수에는 공차 누적과 최대/최소 재료 조건을 검토한다. 볼트·씰·밸브·통로를 그렸다는 사실이 기능 검증은 아니다.

## 실행과 전달

- 가능한 환경이면 소스를 실제 실행해 솔리드를 만들고 형상 유효성·치수·부피·간섭 중 목적에 맞는 항목을 검사한다. 실행 환경·방법·실제 결과를 기록한다.
- STEP은 실제 내보내기·재열기를 확인한다. STL은 단위 전달·닫힘·비다양체 등 출력에 필요한 조건을 가능한 도구로 확인한다. 함수 호출 성공과 제조 적합성을 구분한다.
- 같은 매개변수에서 필요한 뷰·단면·치수도를 출력한다. 모델과 다른 숫자를 그림에 따로 넣지 않는다.
- 실행 원본·버전/실행 방법·필요 출력·가정·검증 범위를 제공한다. 도구가 없으면 가능한 원본과 계획까지만 제공하고 미실행을 밝힌다. STEP/STL 확장자의 빈 파일이나 다른 형식 파일을 만들지 않는다.

디지털 검토는 실제 그립·착좌·누수·하중·탈락·마찰·내구 시험을 대체하지 않는다. 어떤 가설을 확인할 시제품인지와 시험 조건을 연결한다.
